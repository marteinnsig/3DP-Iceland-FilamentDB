Support multiple independent inventory spool records for the same material.

## Architecture
- `NativeMaterialManagerRows` remains the canonical material catalogue.
- New `InventorySpoolItems` SQLite table stores inventory instances and references `MaterialId`.
- One material may have zero, one or many spool records.
- Each spool record owns status, quantity, spool weight, remaining weight, location, batch and purchase metadata.
- Inventory calculations consume spool records rather than material rows.

## Migration
When the new spool table is empty, existing v38.1/v38.2 purchasing fields are copied into one initial spool record per populated material. Existing material fields are retained for backwards compatibility.

# v38.2.0 – Inventory Engine

## Primary objective
Turn the purchasing fields introduced in v38.1 into a verified inventory calculation layer without introducing landed-cost or currency-conversion logic.

## Delivered
- Native `InventoryEngineService`.
- Inventory Summary workspace tab.
- Total, unopened, opened and empty spool counts.
- Remaining weight and percentage calculations.
- Estimated remaining inventory value grouped by purchase currency.
- Row-level inventory validation.
- Verification Center checks and diagnostics section.

## Calculation rules
- Quantity defaults to 1 when blank and must be a non-negative whole number.
- Unopened rows with blank remaining weight use full spool capacity.
- Empty rows calculate as 0 g remaining and flag entered positive remaining weight.
- Remaining weight cannot exceed spool weight multiplied by quantity.
- Estimated value is purchase price prorated by remaining weight.
- Values remain grouped by currency; no exchange-rate conversion is performed.

## Deferred
Landed cost, Cost/kg, Cost/Test, Cost/Print and currency conversion remain v38.3 scope.

# v38.1 – Purchasing Foundation

## Objective
Establish the SQLite-backed purchasing and inventory data foundation without introducing inventory or cost calculations.

## Added fields
Inventory ID, Purchase ID, Purchased From, Supplier URL, Purchase Date, Order Number, Batch Number, Storage Location, Inventory Status, Quantity, Spool Weight, Remaining Weight, Purchase Price, Currency, Shipping and VAT.

## Architecture
- SQLite schema version 8.
- Backward-compatible additive migration through `EnsureColumn`.
- Native Material Manager remains the editing surface and SQLite remains the source of truth.
- JSON transition storage remains readable for compatibility and now serializes the added fields.
- No landed-cost, cost/kg, cost/test or cost/print calculations are included in this release.

## Verification scope
Schema migration, edit persistence, restart persistence, detail-panel grouping, Excel import aliases, archive/duplicate/delete regression and existing engineering verification gates.
